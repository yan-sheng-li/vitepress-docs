# 单体应用连接多个业务数据库

> **场景**：一个 Spring Boot 项目需要连接两个业务完全不同的 MySQL 数据库，表结构也不一样。

---

## 一、核心思路

- **物理隔离**：不同业务的 Mapper、Entity、Service 放在不同的包路径下
- **动态路由**：通过 `@DS` 注解动态切换数据源
- **事务分离**：各业务使用各自的事务管理器

---

## 二、推荐方案：dynamic-datasource（官方组件）

### 2.1 引入 Maven 依赖

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot-starter</artifactId>
    <version>3.6.1</version>
</dependency>
```

### 2.2 application.yml 配置

```yaml
spring:
  datasource:
    dynamic:
      primary: order              # 默认数据源（不加@DS时使用）
      strict: false               # false表示找不到数据源时用primary
      datasource:
        # 订单数据库
        order:
          url: jdbc:mysql://192.168.1.10:3306/order_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
        # 用户数据库  
        user:
          url: jdbc:mysql://192.168.1.20:3306/user_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
```

### 2.3 Mapper 层使用 @DS 注解

```java
// 订单模块 Mapper
@DS("order")
@Mapper
public interface OrderMapper extends BaseMapper<Order> {
    @Select("SELECT * FROM order_table WHERE id = #{id}")
    Order selectOrderById(Long id);
}

// 用户模块 Mapper
@DS("user")
@Mapper
public interface UserMapper extends BaseMapper<User> {
    @Select("SELECT * FROM user_table WHERE id = #{id}")
    User selectUserById(Long id);
}
```

### 2.4 Service 层使用（含事务）

```java
@Service
public class OrderService {
    @Autowired
    private OrderMapper orderMapper;
    
    @DS("order")
    @Transactional
    public void createOrder(Order order) {
        orderMapper.insert(order);
    }
}

@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;
    
    @DS("user")
    @Transactional
    public void updateUser(User user) {
        userMapper.updateById(user);
    }
}
```

### 2.5 跨业务调用（事务说明）

```java
@Service
public class OrderService {
    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private UserService userService;
    
    @DS("order")
    @Transactional
    public void createOrderWithUser(Order order, Long userId) {
        // 调用用户服务（内部会切换到 user 数据源）
        User user = userService.getUserById(userId);
        // 自己的订单逻辑
        orderMapper.insert(order);
    }
}
```

> **注意**：跨数据源操作时，`@Transactional` 无法保证分布式事务。如需强一致性，需引入 Seata 等分布式事务框架，或使用编程式事务手动控制。

## 三、@DS 注解优先级

```
方法级别 > 类级别 > 全局默认（primary）
```

**示例**：

```java
@DS("user")  // 类级别默认
@Service
public class UserService {
    
    @DS("order")  // 方法级别覆盖，使用order数据源
    public void someMethod() {
        // ...
    }
}
```

## 四、项目包结构建议

```
com.yourcompany
├── order                    # 订单业务模块
│   ├── controller
│   ├── service
│   ├── mapper               # 只操作order_db
│   └── entity               # 订单库实体
└── user                     # 用户业务模块
    ├── controller
    ├── service
    ├── mapper               # 只操作user_db
    └── entity               # 用户库实体
```

> 两个业务可以有同名实体类（如都有 `User`），但因包路径不同，不会冲突。

---

## 五、常见问题与解决方案

| 问题                 | 解决方案                                                     |
| -------------------- | ------------------------------------------------------------ |
| **Bean 重复定义**    | 用 `@Primary` 标记主数据源（dynamic 已内置处理）             |
| **跨库事务失效**     | 单库操作各自用 `@Transactional`；跨库需引入 Seata            |
| **Mapper 扫描混乱**  | 不同业务的 Mapper 包路径必须隔离                             |
| **实体类同名冲突**   | 放在不同的包下（如 `order.entity.User` 和 `user.entity.User`） |
| **两个库在同一实例** | URL 中指定不同数据库名即可                                   |

## 六、备选方案：手动配置多数据源

如果不想引入 dynamic-datasource，也可以手动配置，但代码量较大：

```java
@Configuration
@MapperScan(basePackages = "com.example.order.mapper", 
            sqlSessionFactoryRef = "orderSqlSessionFactory")
public class OrderDataSourceConfig {
    
    @Primary
    @Bean("orderDataSource")
    @ConfigurationProperties(prefix = "order.datasource")
    public DataSource orderDataSource() {
        return DataSourceBuilder.create().build();
    }
    
    @Primary
    @Bean("orderSqlSessionFactory")
    public SqlSessionFactory orderSqlSessionFactory(
            @Qualifier("orderDataSource") DataSource dataSource) throws Exception {
        MybatisSqlSessionFactoryBean bean = new MybatisSqlSessionFactoryBean();
        bean.setDataSource(dataSource);
        bean.setTypeAliasesPackage("com.example.order.entity");
        return bean.getObject();
    }
    
    @Primary
    @Bean("orderTransactionManager")
    public DataSourceTransactionManager orderTransactionManager(
            @Qualifier("orderDataSource") DataSource dataSource) {
        return new DataSourceTransactionManager(dataSource);
    }
}
```

> 用户库配置类似，但不加 `@Primary`。
